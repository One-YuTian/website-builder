# Website Builder 0.7.2

## 预览超限修复

旧预览把本地图片、样式和脚本转为Base64嵌入HTML，再将整页gzip/base64放进单次MCP响应。页面资源稍大，便触发project-service的3,800,000字符阈值，被画布错误描述为“生成失败，请压缩图片”。这属于预览传输限制，并不代表网站源文件生成失败。

本次增加两层处理：本地位图/媒体（含HTML、srcset和动态脚本路径）改用不暴露文件路径的预览资源标识，通过现有512KB资源分片通道加载；仍然较大的页面（例如CSS嵌入了大型背景图）用gzip资源描述符传输，客户端分片读取后解压，不再按旧阈值判定生成失败。MCP的read_page入口也使用同一协议。CSS依赖兼容原来的内嵌方式，由页面分片兜底。

前端仅在一批页面全部解码后确认版本，防止中间分片失败时丢失其他页面；失败后可以重试。原图和源网站不被压缩、改写或删减。预览资源注册表仅接收后端已校验的文件或编译产物，未知标识直接拒绝，不向虚拟域名发起网络请求。单资源原有64MB读取保护继续保留。

## 内容与模板规则

- 移动viewport<768px时html根字号必须12px；首轮组件渲染前设置，跨断点同步恢复桌面字阶，监听幂等，不以body字号或transform缩放替代。核对375/767/768/1280视口。
- Header、Footer及移动菜单的Logo必须为真实可加载图片，以img/picture呈现。没有Logo时调用图片技能；纯文本、首字母方块、占位符或自绘CSS/SVG不能冒充Logo。
- 完整首页在页头、页脚、轮播/主视觉和商品列表之外，再组合1–2个不同用途的独立板块，例如分类、品牌故事、精选专题、场景或无虚构承诺的服务说明。不得重复货架、轮播、图片/文案或只改标题凑数；组件内部仍忠实于各自模板。
- 新网站购物车默认components/cart.js抽屉，不默认规划cart.html。只有用户明确独立页需求或保留已有page模式时使用页面方案，互斥规则保留。默认项目计划由13页改为12页；已有计划不自动删除。

## 为什么Shop/About一直重复

候选长期以固定顺序返回，原About的11份摘要/概述几乎相同，无法据此区分布局；历史选择也没有作为选型参考。单靠“由Agent选择”容易沿用熟悉的第一个模板。

本次从实际HTML整理11个About的区域/栅格差异，更新候选摘要、doc/code和CLI读取器，避免继续用通用hero/指标/团队概述误导选型。Shop保留此前的精确布局契约。select现在返回已绑定模板的历史项目使用次数和最近使用时间；没有来源记录的网站不伪造统计。

主技能要求完整新站分别比较至少3个Shop和3个About候选（不足3个则全看），依据品牌、内容长度、图文结构和筛选需求选择，在同样相容的布局中优先较少使用的候选；将比较及理由保存到管理目录，并绑定实际来源供之后统计。不强制随机、轮换或禁用-01；局部编辑继续保留原布局。最终仍由Agent作布局选择，不能声称每个新站必然使用不同模板。
