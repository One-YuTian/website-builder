# Website Builder 更新日志

后续版本在本文件顶部追加，保留全部历史记录。

## 0.9.6 — 2026-11-20

- 新增首页 `+ 商品库` 入口与插件级商品库导入弹窗，支持接口链接（`GET xxx/api/products`）、JSON/文本文件与粘贴导入，以及列表勾选、价格/折扣/评分排序、图片列表主图筛选设置、单条详情与多图预览。
- 支持将商品库原始数据导入项目 `files/data.json`，同输入框存在 `data.json` 时自动递增重命名并同步替换 `ui://` 上下文；输入框展示 `xx件商品` 胶囊并输出 `[商品xx件]` 与 `ui://` 上下文。
- 初始化项目时自动生成 `.gitignore`，默认忽略 `.gitignore`、`files/`、`material/`、`node_modules/` 及常见日志/缓存目录。
- 更新 `website-copywriter` 文案 SKILL：明确 About Us 聚焦品牌介绍而非网站功能说明，隐私政策/服务条款/退换货政策不暴露网站接口、数据或存储逻辑。

## 0.9.5 — 2026-11-19

- 修复 GitLab 预检拉取云端分支时缺少 fetch refspec 引起的 `NoRefspecError`（`Could not find a fetch refspec for remote "origin"`），在 fetch/push 前自动确保远端与 refspec 配置就绪。
- 优化提示词提交消息格式：国家/语言、配色主题、验证模式等标签调整至消息顶部，空一行后紧随用户输入及附件原名，且验证模式去除了括号内的说明文字。
- 修复从会话侧边栏打开项目详情页提示「项目详情尚未绑定」的问题：放行已绑定项目的侧边栏面板握手校验，并在已就绪后不再重复触发握手。

## 0.9.4 — 2026-11-19

- 线上部署冲突覆盖改用以远端与本地为父提交的快进覆盖提交，修复 GitLab 受保护 `main` 分支 `pre-receive hook declined` 强推报错，并取消「以云端为准」选项、保留二次红色强提醒确认。
- 线上部署前增加与预览环境一致的项目完成状态与图片任务校验，未完成时直接拦截提示；Git 提交作者改用用户实际用户名。
- 优化「部署到线上环境」面板：精简预检通过展示、按各阶段实际高度动态定位、固定顶栏与底栏按钮、中间内容支持自定义滚动条，并在检查阶段保持「返回」可用且兼作取消发布。
- 插件配置面板测试连接成功统一改用顶部 Toast 提示；首页需求提交成功后自动清空输入框、草稿缓存及配色/国家语言选项（保留验证模式）。

## Website Builder 0.7.5

### 完成一页，立即写一页

主技能、页面规范与工具说明改为：先准备共享依赖，当前页完整代码生成后立即格式化、写文件并检查ready，随后才开始下一页；不能先在数组/脚本/对话中生成全站代码再统一输出。website_write每次最多接收一个HTML文件，可携带当前页共享依赖；多HTML请求会在任何写入前被拒绝。其他页面保持queued，后续页失败不回滚已完成页。单页文件仍原子替换。

### 导入图片只在渲染时拼CDN

导入后的productData、SDK返回对象以及购物车映射中的main_image/images/image继续保留原相对路径。图片引用时显式使用storeData.imageUrl(path)或productImageUrl(path)，例如将/img/a.jpg解析为https://cdn.mreceix.com/img/a.jpg，再赋给img.src、srcset或背景图。辅助函数不改变商品对象，不安装自动图片拦截；绝对HTTP(S)图片仍可用。源JSON文件保持原字节，不参与格式化或地址替换。

### SDK采用二次分类

源分类过多时，不再机械保留前5个源类加More。工具先报告源分类摘要，需要时返回classification_required而不写数据，由主技能根据真实语义生成覆盖全部源分类的category_map后重试；一致的parent_category也可推导归类。摘要可分页读取，不需Agent直接读取整份JSON。

成功导入后，运行商品category为二次归类；SDK.categories/get/list/filter均读取新类，source_category保留原类追溯。catalogGroups与新类一致，分类菜单和Shop筛选共享同一分类字段。source_category_count报告源类数，category_count报告实际SDK类数；通常5–6主要类，信息不足不造空类。分类尚未完成不能转Mock；只有JSON/核心字段无法识别时仍走原Mock回退。来源、映射和运行视图散列保存在管理目录，源JSON不改。

### 本地Prettier统一输出

内置Prettier standalone 3.6.2及Babel/Estree/HTML/PostCSS解析器文件和MIT许可证，位于assets/prettier，构建复制到dist/runtime/prettier。不新增npm依赖、不运行npm install/npx，格式化时不联网；文件来源与SHA256在assets/prettier/source.json，工具仅在插件使用，不发布到网站。

write和finish对完整HTML（含内联script/style）及输出JS/MJS/CSS/JSON格式化；旧hook也使用同一路径。统一options.json：2空格、printWidth 100、JS单引号与分号、trailingComma all、LF、HTML属性双引号、JSON双引号层级缩进。100是折行目标，不强行截断长URL或素材串。

语法错误不覆盖原文件；HTML内联JS/JSON也检查。未闭合HTML保持未完成，不允许Prettier修复成虚假的ready。已完成的页不受下一页错误影响；格式化幂等，不改变页面业务或图片字节。

### 验证

通过TypeScript及Vite/tsup构建。新增output专项验证一页已ready、下一页仍queued、批量HTML拒绝、HTML/内联JS/CSS/JS/JSON格式化、错误保护、幂等与业务等价；无node_modules的隔离目录也可使用本地格式化器。

导入专项验证源JSON散列不变、SDK/运行图字段仍为相对路径、渲染辅助函数得到CDN URL且不改对象、SDK分类/过滤使用映射后的类、源类别追溯、201源类摘要分页和Mock回退。既有项目、模板、账户/交易、Toast、功能、大型预览与在线CDN回归通过。

测试使用隔离目录，不修改用户的路径配置；本轮未导入用户实际商品或自动批量重写历史网站。重新安装/重载0.7.5后使用新写入协议与适配流程。

Prettier的本地standalone调用方式依据[官方说明](https://prettier.io/docs/browser)，格式选项参见[官方选项文档](https://prettier.io/docs/options)。

## Website Builder 0.7.2

### 预览超限修复

旧预览把本地图片、样式和脚本转为Base64嵌入HTML，再将整页gzip/base64放进单次MCP响应。页面资源稍大，便触发project-service的3,800,000字符阈值，被画布错误描述为“生成失败，请压缩图片”。这属于预览传输限制，并不代表网站源文件生成失败。

本次增加两层处理：本地位图/媒体（含HTML、srcset和动态脚本路径）改用不暴露文件路径的预览资源标识，通过现有512KB资源分片通道加载；仍然较大的页面（例如CSS嵌入了大型背景图）用gzip资源描述符传输，客户端分片读取后解压，不再按旧阈值判定生成失败。MCP的read_page入口也使用同一协议。CSS依赖兼容原来的内嵌方式，由页面分片兜底。

前端仅在一批页面全部解码后确认版本，防止中间分片失败时丢失其他页面；失败后可以重试。原图和源网站不被压缩、改写或删减。预览资源注册表仅接收后端已校验的文件或编译产物，未知标识直接拒绝，不向虚拟域名发起网络请求。单资源原有64MB读取保护继续保留。

### 内容与模板规则

- 移动viewport<768px时html根字号必须12px；首轮组件渲染前设置，跨断点同步恢复桌面字阶，监听幂等，不以body字号或transform缩放替代。核对375/767/768/1280视口。
- Header、Footer及移动菜单的Logo必须为真实可加载图片，以img/picture呈现。没有Logo时调用图片技能；纯文本、首字母方块、占位符或自绘CSS/SVG不能冒充Logo。
- 完整首页在页头、页脚、轮播/主视觉和商品列表之外，再组合1–2个不同用途的独立板块，例如分类、品牌故事、精选专题、场景或无虚构承诺的服务说明。不得重复货架、轮播、图片/文案或只改标题凑数；组件内部仍忠实于各自模板。

### 为什么Shop/About一直重复

候选长期以固定顺序返回，原About的11份摘要/概述几乎相同，无法据此区分布局；历史选择也没有作为选型参考。单靠“由Agent选择”容易沿用熟悉的第一个模板。

主技能要求完整新站分别比较至少3个Shop和3个About候选（不足3个则全看），依据品牌、内容长度、图文结构和筛选需求选择，在同样相容的布局中优先较少使用的候选；将比较及理由保存到管理目录，并绑定实际来源供之后统计。不强制随机、轮换或禁用-01；局部编辑继续保留原布局。最终仍由Agent作布局选择，不能声称每个新站必然使用不同模板。

### 生产目录

website_project现在返回directory和metadata_directory。directory是可发布的生产目录，只保存网站运行所需页面、脚本、样式、组件和正式素材；js/data.js是实际消费的唯一商品运行数据，可以保留。原始数据源、样本/seed、抓取响应、生成脚本、草稿、候选图、提示词、截图、测试文件和报告不进入生产目录。

### 图片和文案协作

图片技能明确先读取宿主imagegen技能，再调用其内置image_gen工具，按实际内容、槽位尺寸、比例、主体位置和文字留白生成。通常生成无字图，由HTML承载文案；Logo必要品牌字样或用户明确要求的图片文字除外。优先一张高质量主图自动裁切适配各端，无法保持主体与留白时才生成多端版本。ICON优先单色图形和透明背景，需要实底时采用统一纯色。

文案技能按场景决定长度：导航/按钮/提示短而清楚，Banner/页脚精炼，About Us和隐私政策可分节充分展开，避免重复空话；不编造业务事实、具体时效、安全保障或其他承诺。About Us有必要配图时可调用网站图片技能，政策页不强行加装饰图。实际已实现流程可客观描述，缺失业务资料明确列为待提供。

主技能对缺少的非商品文案、品牌/叙事图片和Mock商品数据主动调用对应技能；已有有效内容复用，不为了调用技能重建。图文不得遮挡主体、人物面部或关键物体，叠字只使用真实留白，优先选择相容的分栏/上下图文模板。逐端检查换行、裁切、清晰度与文字安全区。

### 必备导航

Header桌面导航及移动菜单都必须有Home、Shop、About Us、Contact Us四项的目标语言菜单，链接到真实存在的首页、商品列表、关于和联系页面。不能只放页脚、空链接或在某个断点隐藏且无替代入口。模板导航槽位不足时选择相容Header模板，用户明确要求优先于模板演示菜单数量。

### 验证与生效范围

已通过TypeScript、Vite/tsup构建、features、projects、templates及commerce回归。新增检查确认生产目录无控制清单/草稿/截图，管理记录正确分流，常见临时/报告写入被拒绝，旧项目读取兼容且旧文件不被改写。既有响应式Shop、登录与交易状态、截图就绪和5/7列画布检查继续通过。
