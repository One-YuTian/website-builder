# Home套用与有限自由组合（生成硬约束）

本规则约束生成决策和实施过程，不属于网站验收指标，不新增代码校验、相似度评分或ready门禁。用户明确指定不同结构或范围时按其要求；已有网站局部修改不借此重排整页。

## 默认沿用选定组合

选定Home后，以其Component Chain及主体板块顺序为默认方案，尽量直接套用，不能每次又重组为惯用的“大横幅＋服务区＋商品区＋故事区”。Home代码仍是伪代码；实际实现依据来自组件链中各个独立组件的完整HTML/JS/CSS，而不是Home伪代码或概要尺寸。

Header/Footer可更换合适的独立模板，不计入主体自由组合额度。主体默认零自由调整；有明确品牌、内容、分类去重或功能理由时，单次首页生成最多自由组合1–2个主体板块，其余沿用原选型与相对顺序。不是每次必须改满2个，也不能把“非百分百还原”理解为整页自由设计。

自由组合包括替换、新增、删除或移动主体板块，每项调整都计入最多2项的额度；同一个来源板块一次替换只计1项，新增、删除和移动不得藏在“替换”说明里。换独立组件型号也属于替换，不能通过连续改选来源规避额度。改文案、图片、SDK数据、统一品牌色/字体和允许的全局主题配置不算自由组合。自由组合不授权重画被选中组件的核心布局；换型仍读取并套用新组件的真实源码。

## 板块数量保持接近

以原选定Home去除Header/Footer后的主体逻辑板块数为N，成品主体数M必须在N−1到N＋1之间。例如原有5块，成品允许4–6块；即使自由调整不超过2项，也不能输出3块或7块。

按组件链的独立主体槽位计数，不把一个组件里的轮播slide、辅助Banner、分类入口、卡片、tab或PC/移动双结构拆成多块；这些内部区域仍需按源码完整实现。原链中两处独立货架槽位分别计数，不能合成一个货架后声称两块都保留，也不能拆/合板块来凑数量。选择其他Home必须先有真实选型理由，不在实现后倒改来源以让数量合规。

原组合已经有足够的特色板块时，不为旧版“额外1–2板块”提示再加一遍。分类去重优先在自由额度内替换为其他用途板块，尽量保持数量；所有模板模块仍允许使用，文案按文案技能策略填充。

## 开发时落实来源

1. 写首页前列出原主体区域及顺序，区分独立槽位与组件内部区域；在metadata_directory/website-builder.design.json简记Home ID、原链、N、计划输出链、M，以及0–2项自由调整的来源/理由。记录辅助实际实施，不代替成品。
2. 逐个读取最终使用组件的完整源码，列出实际区域、断点、列数、尺寸/比例与交互。Overview、摘要、区域说明与HTML/JS/CSS冲突时，以真实实现为准，并记录冲突，不混用概要参数补画。
3. 从源码结构替换骨架、文案、图片并接入SDK；保留实际父子层级、辅助Banner、分类入口、独立货架和推广区域。需要改核心布局时重新选相容组件，计入自由额度，并在改代码时同步更新来源记录，不能保留Promotion-02等旧ID却实际输出自画结构。
4. 先确定实际图片槽位比例、断点和文字容量，再交给图片/文案技能准备素材；不反过来用过长正文撑大横幅、改变列数或比例。
5. 开发者分别自查加载/交互与所选来源区域的落实情况，覆盖375、767、768、1023、1024、1280px等实际切换；按断点查显隐、比例和区域可达性。加载成功、截图可用、ready只证明其各自结果，不证明模板落实。修复偏差先回到来源组件，不继续给自画结构补规则。

以上是生成阶段执行约束和开发自查，不写进website-acceptance的验收清单，不输出数量/额度/还原度验收分数，也不以此判定页面ready。验收继续看页面布局合理、适配合理及原有资源/功能表现。
