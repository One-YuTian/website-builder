# GitLab 仓库与官网部署（暂时停用）

当前入口已注释，保留本文件和实现供后续接口恢复使用。当前部署请使用[R2流程](r2-deployment.md)，不调用本文件中的GitLab工具。

仅在用户明确要求创建/同步仓库、推送或部署时使用；普通建站结束仍只本地提交，不自动发布。开发此功能时只能使用隔离的模拟接口/仓库，真实 GitLab 由用户亲自验证。

## 插件配置

通过官方 `openai/settings` 结构化设置扩展，在 Codex 插件管理页展示配置，不依赖自定义 manifest 字段。PROJECT_DIR 固定为当前目录，GITLAB_TOKEN 使用字符串输入框，输入框回显当前值，明文保存，清空后保存即可删除；不提供额外的“配置 Website Builder”工具入口。首页与发布窗口先检测宿主 requestModal；有接口且调用成功时打开独立 UI，接口缺失或宿主拒绝时自动使用内部模态窗口，保证按钮可用。

| 配置 | 默认与作用 |
| --- | --- |
| PROJECT_DIR | 自动读取插件实际项目资源目录；只读，保存或重新读取时恢复为实际路径，同名环境变量不能覆盖它 |
| GITLAB_HOST | 空；无协议默认 HTTP，内网只支持 HTTP 时填写 http://域名或IP:端口，显式 https:// 才启用 TLS；可带部署子路径，不含账号、密码、查询或片段 |
| GITLAB_IP | 空；GitLab 的实际 IP，需 OPEN VPN 可达，后端以该 IP 连接并保留 HOST/TLS 校验 |
| GITLAB_TOKEN | 空；在配置页输入，不在对话收集或回显；本机明文保存，配置表单及原生设置回显；配置位于独立用户配置目录，不写进官网或仓库 |
| GITLAB_WEBSITE_DIR | 空；网站仓库所属分组/子分组地址或路径 |
| GITLAB_WEBSITE_DEPLOY_DIR | 空；用于创建部署标签的仓库地址或路径 |
| GITLAB_DEFAULT_BRANCH | main；部署仓库中打标签的基准分支，官网源码本地/云端仍遵循 main 规则 |

本机已保存值优先，未保存字段读取同名 GitLab 环境变量。Token 输入框反映实际当前值，清空后保存会清除本机配置值；未提供该字段的更新保留现有值。旧版加密值兼容解密读取，普通读取/保存后转换为明文，原生只读读取不修改文件。已有配置时 PROJECT_DIR 也不会从用户输入取值。部署/确认期间不能从配置页修改配置；先取消，再修改。

首页配置入口位于“开始构建你的网站”标题行右端，与输入面板右侧对齐。内部配置弹窗左侧属性表单、右侧连接测试，窄屏纵向排列。

## 连接测试与 TLS 故障

Codex 插件设置页提供“测试连接”（website_settings_test），只读取已保存配置；插件内配置窗口使用当前输入测试，不保存。测试依次核对地址、TCP/IP、HTTPS 的 TLS/证书、Token 用户、网站分组、部署仓库和基准分支。失败后停止后续检查，返回失败阶段、原始错误与排查方向，不创建仓库、不提交、不推送、不创建标签。HTTP 配置明确跳过 TLS；总测试超时45秒。

已知服务仅支持HTTP时，GITLAB_HOST必须使用http://（或不写协议，默认HTTP），不要把内网HTTP地址写为https://；GITLAB_IP只填写IP，端口配置在HOST。分组/部署仓库如填写完整URL，协议与HOST保持一致。HTTP测试跳过TLS，API及Git传输也走HTTP；不自动把明确的HTTPS配置降级。

EPROTO / tlsv1 alert internal error / alert 80 表示 TLS 对端返回 internal_error，不能据此判断 Token 错误，也不能据错误字符串认定使用了 TLS 1.0。优先核对 HOST 的 HTTPS 域名与端口、IP 对应的服务、VPN/网关及反向代理 TLS/SNI 日志。请求固定连接 GITLAB_IP，保留 HOST 域名用于 SNI、HTTP Host 和证书验证；IP 不作为 SNI。保持证书校验，不通过关闭验证或自动降级协议绕过故障。内部CA需由插件Node运行环境信任。

## MCP 工具

- website_gitlab_create：在已验证的网站分组创建名为真实官网域名（www.xxx.xxx）的私有空仓库。创建前必须用户确认。
- website_gitlab_bind：空仓库可绑定 origin；已有版本或差异时展示本地/云端选择。选 local 只绑定地址，不覆盖本地、不强推；选 cloud 先保存完整本地项目及元数据备份，再克隆并替换为云端当前 src/README 项目格式。无法识别的云端格式不自动迁移，不覆盖本地。
- website_gitlab_commit：先检查远端与分支状态，再本地提交；不推送。异常退回用户确认和系统 Git。
- website_gitlab_push：先检查冲突，再提交并普通推送 main；拒绝非快进、云端领先或分叉时返回 GIT_CONFIRMATION_REQUIRED，不能自行强推。
- website_deploy：执行下面的严格流程，最终通过 API 创建部署仓库的注解标签。

工具默认 action=run；action=status 查询当前锁与结果及 cancellable，action=cancel 可以取消检查、创建/绑定、提交、推送和最终核验中的任务。仅创建发布标签的请求发出后不可取消。取消先标记请求并中止可中断的网络请求，正在进行的文件/Git操作收尾前继续持有写锁，不允许重复取消提前解锁。取消不回滚已经完成的提交、仓库创建或推送，不能继续创建标签。操作只针对真实当前会话绑定项目；UI按当前面板绑定项目操作。

## 确认与部署顺序

1. 明确真实官网域名和测试/正式环境。域名必须是单一 www.xxx.xxx，不含路径、端口或协议，不能根据临时预览域名猜测。
2. 依次核验配置、GITLAB_IP 连通性、Token `/user` 身份、网站分组、部署仓库、部署基准分支及官网仓库的实际身份/版本。IP 不通时提示检查 OPEN VPN；前一步失败即停止，不跳过检查。
3. 官网仓库不存在则询问是否创建指定仓库；创建确认不等于发布确认。已有仓库则检查地址、分支和版本；初次绑定存在差异时让用户决定内容来源。后续部署不重复创建，但每次仍检查仓库真实存在及本地/云端版本。
4. 对实际要发布的内容进行确认：域名、环境、仓库及版本。MCP 优先使用宿主原生 elicitation 表单。宿主不支持时工具返回 input_required/confirmation_required；Agent必须使用 Codex 提问对话框（如 request_user_input_async），等待真实用户回答后携带确认ID和明确决定继续。不能自填 approved、把默认选项/超时当确认，不能用普通“继续执行”的旁白代替提问。
5. UI优先通过宿主模态窗口打开独立发布资源，不支持时使用内部模态窗口，选择“测试环境”或“正式环境”，不展示标签前缀/命名串；创建、内容覆盖与发布为不同确认。cloud必须明确告知会先备份再覆盖。创建标签请求发出前均可取消；确认具有时效且一次性、绑定项目/会话/域名/环境/版本，不能复用到别的网站。
6. 确认后重新检查连接、配置及双方版本，核对页面完整、实际源码被Git跟踪、没有生成中的图片、分支main、仓库地址正确、没有冲突。提交最新本地文件并普通推送，再读取云端main确认与本地版本一致。任何异常先停止，由用户决定合并等方式后使用系统Git处理。
7. 最终再次核对源码、配置、本地分支/HEAD、远端版本及部署基准未改变；仅全部通过才在部署仓库通过 GitLab Tags API创建标签。ref采用最近核验的GITLAB_DEFAULT_BRANCH提交SHA，message仅一个已确认的官网域名。

正式环境标签为 release-YYMMDDHHMM，测试环境为 test-YYMMDDHHMM，时间固定 Asia/Shanghai。标签已存在则不覆盖、不复用，下一分钟重新确认；单个标签不承载多个官网，不执行CLI的git tag/git push来代替标签API。

仓库创建和标签使用 GitLab API；绑定、fetch/clone、提交和推送使用插件内置 isomorphic-git。冲突操作仅在用户明确确认后由系统Git处理，不自动merge/rebase/reset/stash/force。普通建站的“不推送”规则只在这类已明确确认的推送/部署请求中获得对应范围授权。

## 只读与结果

从检查到确认/执行阶段，项目受跨进程部署锁保护，UI画布不可编辑，普通MCP写入、改页、图片发布及删除被拒绝。Agent不得绕过锁直接写源文件；外部文件/索引/HEAD/配置变化会使确认失效或中止发布。取消后等待执行收尾再解除锁，执行中用租约心跳维持锁，失效确认必须重新检查。关闭宿主发布窗口时也请求取消可取消阶段；标签请求已发出则保留任务直到结果返回。

返回 deployment_triggered 表示发布标签已创建、已触发流水线，不代表网站已经上线；用户在真实 GitLab 验证权限、私有CA/网络、流水线与最终访问。API结果未知或返回不匹配时先人工核对标签，不自动重试创建。Token 不进入模型输出、网页源码、Git远程URL或提示消息。
